# 앱 전수 감사 및 구현 계획 (2026-08)

앱의 모든 탭·페이지·버튼을 기계적으로 훑어서 **동작하지 않는 것**과 **디자인이 어긋난 것**을 전부 찾은 결과다.
판정은 추측이 아니라 코드 검사로 했다(핸들러 없는 `<button>` 전수 추출, 토큰 미사용 클래스 카운트 등).

## 2. 존재하지 않는 기능 (죽은 UI)

핸들러가 아예 없는 `<button>` **24개**를 전수 추출해 분류했다.
아래는 그중 **사용자에게 보이는데 눌러도 아무 일도 안 일어나는 것**들이다.

### 2-A. 하단 탭 3개 — 가장 심각

`components/layout/BottomNav.tsx:39,43,47` — **데스크톱이 아닌 모바일 하단 탭**에 `グループ` / `メール` / `メッセージ` 3개가 있는데 **전부 `onClick`이 없다.**
앱의 최상위 내비게이션에 죽은 버튼이 3개 있는 셈이라 우선순위가 가장 높다.

> 참고: `Tab` 타입은 `'today' | 'meishi' | 'community'` 3개뿐이라, 이 3개는 애초에 갈 곳이 없다.

**계획**: 아래 3안 중 택1 — **A안 권장**
- **A. 제거** (권장, 반나절 미만): 이전에 `採用公告`/`コネクト` 탭을 같은 이유로 제거한 선례가 있다(CLAUDE.md 6번). 죽은 내비를 남겨두는 것보다 낫다.
- B. `準備中` 상태로 명시: 눌리긴 하되 "준비 중" 시트를 띄움. 최소한 거짓말은 아니게 됨.
- C. 실제 구현: 메시지/메일은 백엔드가 필요해 대형 과제(아래 4장 참고).

### 3-B. `alert()` 11곳 — 네이티브 앱에서 부적절

`alert()`는 iOS에서 "localhost 내용:" 같은 시스템 문구가 붙어 나오고 디자인을 전혀 따르지 않는다.
ui-ux-pro-max의 `Submit Feedback`(severity **High**), `Toast Notifications`(3~5초 자동 소멸), `Confirmation Dialogs`(severity **High**) 위반.

| 위치 | 건수 |
|---|---|
| `MeishiMapView.tsx` | 4 |
| `App.tsx` | 3 |
| `hooks/useAccountSettings.ts` | 3 |
| `settings/SettingsModals.tsx` | 1 |

**계획**: 토스트 컴포넌트 1개 + 확인 다이얼로그 1개를 만들어 전부 치환. 관리 콘솔의 `Badge`/`Button` 패턴 재사용 가능.
→ **1일.**

## 4. 백엔드가 없어서 막혀 있는 것

기능 자체보다 **서버 부재**가 병목인 항목들. 개별 구현이 아니라 **한 번에 서버를 세우는 결정**이 선행되어야 한다.

| 기능 | 필요한 것 |
|---|---|
| 알림 실제 발송 | FCM 발송 서버 (토큰 저장은 이미 됨) |
| 문의 답장 메일 | Cloud Functions + 메일 프로바이더 (현재 `mailto:`로 우회) |
| 메시지/메일 탭 | 실시간 메시징 백엔드 |
| LINE 로그인 | 배포된 HTTPS 서버 (로컬호스트 불가) |

**계획**: Firebase Cloud Functions 도입을 한 번에 결정하면 위 4개가 동시에 풀린다. → **별도 논의 필요.**
